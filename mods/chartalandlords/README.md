# ChartaLandlords —— 斗地主牌局扩展

在 [Charta](https://modrinth.com/mod/charta) 的牌桌系统上增加一个可完整游玩的 **斗地主** 牌局：
3 人局（54 张）与 4 人局（108 张两副牌），含叫分 / **抢地主**、**明牌 / 加倍**、完整牌型判定、
三档难度的自动出牌对手，以及一段客户端现场合成的中国风 BGM。

> 本模组是 [ChartaLandlords](../../README.md) 工作区的第一个模组；命名空间、端口、构建与校验约定
> 都记在工作区 README 的「规范化约定」一节。

## 环境与依赖

| 组件 | 版本 |
| --- | --- |
| Minecraft | 1.21.1 |
| NeoForge | 21.1.248（`neoforge.mods.toml` 声明为 `[21.1.248,)`，21.1.251 等更高版本同样可用） |
| Charta（必需） | 1.2.5（`charta-neoforge-1.21.1-1.2.5.jar`，已放在 `libs/`） |
| JDK / Gradle | 21 / 9.2.1 |
| 模组名 / 产物名 | `ChartaLandlords` / `charta-landlords-<version>.jar` |
| mod_id（资源命名空间） | `chartalandlords` |

`build.gradle` 里 Charta 只做 `compileOnly`；开发运行时由 `syncDevMods` 任务把 `libs/*.jar` 复制到 `run/mods`，
这样 FML 才会把它当模组加载（同时放进运行类路径会导致 Charta 被加载两次并报模块包冲突）。

安装到真实整合包时，把本模组 jar 与 Charta jar 一起放进 `mods` 目录即可。

## 怎么玩

1. 摆一张 **牌桌** 与 3~4 把 **游戏椅**（椅子朝向牌桌）。
2. 自己坐一把椅子；用牵引绳把生物（村民、牛等）拉住后右键椅子，让它坐上去当 AI 对手。
3. 把牌堆放上牌桌：**斗地主牌堆（54 张）** 打 3 人局，**斗地主双副牌堆（108 张）** 打 4 人局。
4. 右键牌桌，在牌局列表中选择「斗地主」。
5. 决定地主：默认是**叫分**（1/2/3 分或不叫），打开「抢地主模式」后变成一轮 **抢 / 不抢**。
6. 地主收底牌 → 进入 **明牌 / 加倍** 阶段（可关）：每人选一次 `明牌` / `加倍` / `跳过`。
7. 出牌：点手牌选牌、按「出牌」，或「不出 / 提示 / 撤回」。

游戏内含一份「如何玩」说明（牌局界面左上角 `?` 按钮），列出全部牌型与比较规则。

### 界面

- **顶部座位条**：每个座位一块染色卡（含生物头像）、名字、`地主/农民` 徽章、**`明` / `倍` / `×4` 个人倍数徽章**、
  剩余张数、上一手摘要，以及第二行右侧**始终**显示（`0` 也显示）的跨局累计分数；
  当前行动方有金色描边，描边按 250ms 呼吸（明牌 / 加倍阶段则点亮「还没决定」的人，因为那一阶段没有「轮到谁」）。
- **表态牌子**：叫分 / 抢地主与明牌加倍阶段，每个人的名字后面会跟一块小牌子写明他表了什么态 ——
  抢地主模式下是 `抢`（亮黄）/ `不抢`（灰），叫分模式下是 `N分`（绿）/ `不叫`（灰），还没轮到的人不画。
  以前状态行只写「已抢 2 次」，根本看不出**是谁**抢的；进入出牌阶段后这块牌子就不再画，
  信息交给右侧的 `地主/农民` 与 `明/倍/×4` 徽章。
- **状态行**（座位条下方）：左侧是局面（轮到谁、地主是谁）、`底分 · 炸弹 · 抢 · ×倍数` 与 `AI：均衡`；
  右侧是**当前选牌的即时反馈** —— `对子（2 张 · 可压）` / `牌型不合法` / `可压不过`，颜色随之变化。
  明牌 / 加倍阶段的左侧追加倒计时与**我的个人倍数**（开关按下即生效，所以确认之前就能看到自己押了多少）。
- **中间两带**：`出牌区`（自己选出的牌）、`上一手`（桌面上的牌），各带左侧标签与底色，空带自动压暗。
  **底牌不再独占一条牌带**：它在面板右上角画成 3 张<b>小牌预览</b>（和记牌器同一块区域），
  把原来那条 52.5px 的整行高度还给了牌桌。
- **底部手牌带**：两行两段。
- **绘制方向统一为一条规则**：*屏幕位置越靠下的一行，画得越晚*。因为牌行高 52.5 而行距只有 11~14，
  相邻行必然叠压，这条规则保证每一行被压住后露出的都是**左上角点数**（而不是一条底部花色）：
  手牌后排露出点数、最下面一行完全可见；上一手不被底牌压住（最低行 42px 可见）；出牌区完全可见；
  长牌型需要 2~4 行时逐行露出点数。这条不变量由 GameTest 对全部 11 个绘制槽位断言。
- **右侧动作列**：三组按钮共用同一条底部基线、互斥显示 ——
  叫分时 `叫 1/2/3 分` + `不叫`（抢地主模式下只留 `抢地主` + `不抢`）、
  明牌 / 加倍时 `明牌` + `加倍` + `确认`（前两颗是开关，会回显 `已明牌` / `已加倍`）、
  出牌时 `出牌` + `不出` + `提示` + `撤回` + `整理`；
  每颗按钮都有 tooltip；该列永远排在 Charta 自带的「玩法 / 选项 / 牌堆 / 记牌器」四个按钮下方，不会互相压住。
- **记牌器**：贴着那四个按钮横带的下方，横跨面板显示 15 个点数各还剩几张没露面；为 0 的格子自动压暗。
  空间够时排成 3 行 × 5 列（格子大、好读），不够自动退化成 1 行 15 格，再不够才整块跳过。
  数据来自服务端对「整副牌 − 自己已见」的推算（手牌、**选牌区**、桌面、弃牌堆、
  **还捏在地主手里的底牌**、以及**别人明牌的手牌**都算已见）。
  这条不变量由 GameTest 逐局、逐座位、逐点数与独立算出的期望值比对。
- **看牌界面**（记牌器标题行右侧的 `看牌` 徽章，或快捷键 `V`）：点开一页把**每家的手牌**与**底牌**
  一次摊开——自己与已明牌的座位画**正面牌**，其余座位按**真实张数**画牌背。
  - 它是**换一个界面**（Charta 自己的牌堆 / 历史界面就是这么做的），不是牌局界面上盖一层：
    牌局界面此时根本不渲染，所以不存在任何图层争夺；牌用框架的 `CardWidget` 画，
    悬停立体感、卡牌名 tooltip、发光后处理全部白拿。左上角返回键 / `ESC` / 再按一次 `V` 回牌局。
  - 「明牌了但看不见」在这里有了第二个出口（第一个是牌桌上那圈翻正的牌），
    而且**不需要新协议**：明牌展示槽、每家张数、底牌展示槽本来就在菜单里同步着。
  - 明牌展示槽现在**不画在界面上**（它是屏幕外的数据通道）：以前 20 多张牌挤进 150px
    就是一条白色糊条，比不看还难读，所以改成这个可以摊开看的整页。
  - 牌背不进控件表，直接贴图：藏着的座位动辄 25 张牌背，全做成控件一帧要几百次绘制 +
    一百多次发光缓冲切换，而牌背本来就没有牌面可看。
- **拖拽排序看得见**：按住手牌拖动时，那张牌会**跟着鼠标走**（借用框架「手上牌」那条绘制路径——
  它在牌局界面的最上层 `z+100`，所以一定压在手牌之上），手牌带上方同时出现一个金色箭头 +
  一条竖线指出插入位置；指示位置与松手后的落点由同一支扇形算法算出（`DoudizhuMenu.cardLeftX`），
  不会出现「线在这里、牌插到那里」。判定为拖拽的阈值从 4px 提到 6px，点击选牌不再被手抖吃掉。
- **BGM**：进牌桌自动播放一段 150 BPM 的中国风循环，**纯客户端、用原版音符盒音效现场合成**（见下）。
  记牌器标题行右侧有一枚 `♪ 音乐 开/关` 徽章，**点一下即切换**；音量跟随原版的「音乐」滑条，
  把音乐拉到 0 就等于静音。
- **新出牌高亮**：桌上换牌时，上一手带会闪一次金色外框（用 Charta 自带的槽位高亮，服务端不参与）。
- **牌型明细**：`上一手` / `出牌区` 的标签下面会写出**牌型与张数**（例如 `炸弹 ×4`）。
  牌带只露出牌的窄条，四张 10 的炸弹和一张 10 在缩略图上几乎一样，写明牌型就不会再误读。
- **操作**：左键点手牌放入出牌区（点选中的牌退回手牌）；**右键界面任意位置**一次性撤回全部选牌；
  **反复按「提示」**在候选之间轮换（从最便宜到最贵，炸弹排最后；进度显示在状态行，不再刷聊天栏）。
- **快捷键**：`回车` = 出牌、`空格` = 不出（按下时按当前是否可用决定，不会误触发）、
  `V` = 打开看牌界面（界面里再按 `V` 或 `ESC` 回牌局）。
  按钮列在屏幕右侧，每次出牌都要把鼠标横跨半个屏幕，这两个键就是为它准备的。
- **手牌手动排序**：**按住手牌拖到别的位置**即可调整顺序。拖动时那张牌跟着鼠标走、
  手牌带上画着插入位置的箭头与竖线，松手时按它插入，其余牌依次让位；
  落在空白处就插到那一段的开头，拖到手牌以外则当作一次普通点击（不会把操作吞掉）。
  - 一旦拖过，这个座位就切到**手动牌序**：出牌、选牌都只做「删掉打出去的那张」，
    **整只手牌不再重排**，所以位置不会每出一手就整体跳一次。
  - 界面上的 **`整理`** 按钮清掉手动牌序、按点数重排一遍，是回到默认顺序的出口。
  - 地主拿到底牌时，如果正在用手动牌序，三张新牌会**接在手牌末尾**（好找），并提示可以拖走或整理。
- **出牌保形**：非法出牌**不再清空选牌**——以前点错一次就把选牌整批退回手牌、得从头再选，
  现在选牌原地保留，拿掉一张就能直接重试（机器座位仍然会把牌退回，避免抱着非法牌死循环）。

### 世界里的那张牌桌（不开界面也能看懂）

牌桌只有 1 格大，一张牌 0.156 格宽、名牌文字约 0.29 格高——**任何悬浮在牌桌上的字都比牌还大**，
从任何角度看都是糊的。所以世界里的信息全部改用**牌本身的位置**表达，一个字都不写：

| 想表达 | 做法 |
| --- | --- |
| 每家还剩几张 | 各座位的**手牌扇形整局保留**（以前第一轮出牌结束就收走），并且**待在自己那个牌槽里**（`FAN_PUSH_OUT = 0`）；早先版本又往外推了 0.24 格，结果只有「轮到谁」那一家看着像在槽里，其余三家都偏到桌外 |
| 谁是地主 | 地主面前**横放着一张扣着的牌**（「地主牌」）：叫分阶段那叠底牌是摆着的，开牌之后桌面只留这一张标记，真正的底牌摊在界面里（右上角底牌预览 + 「看牌」页）；标记的落点由「地主自己的出牌区落点往回退 0.5 格」算出来，**一定夹在他的扇形与他自己打出的牌之间**，而且比扇形多转 90°，一眼能看出是标记而不是谁打的牌 |
| 上一手是什么 | 上一手牌摊在**桌心**，位置由框架的卡槽同步 |
| 上一手是谁打的 | 上一手牌从桌心**往出牌者那一侧偏 26%**（`PLAY_DRIFT`），并且**按出牌者的朝向摆放**（`angle` / `stackDirection` 抄该座位的扇形）——不同人出的牌朝向不同，正面朝着出牌的人 |
| 现在轮到谁 | **轮到谁，谁那圈牌就往桌心推出来 0.19 格**（`FAN_TURN_PUSH`）；换人时上一家自动退回（客户端位置插值，看上去是滑过去） |

- 推牌的偏移量记在「基准位置」上（`fanRest`），所以跟执行顺序无关：重新发牌再摆位也不会越推越远。
- **所有摆位都以一个固定的「桌心」常量（`TABLE_CENTER_X/Y`）为基准**，而不是拿 `playArea` 的当前位置当中心：
  上一手牌会动，用它当基准的话「扇形推出多少」「底牌缩进多少」「轮到谁推多远」会跟着这手牌一起变，
  同一局里每次轮到同一个人的位移都不一样（这条是被 GameTest 抓住的：推出去 44、退回 42.66）。
- **朝向改动会走「完整卡槽包」**：`GameSlotPositionPayload` 只带 x/y/z/angle，`stackDirection` 只在
  `GameSlotCompletePayload` 里。所以出牌区 / 底牌都是**先 `setCards`（把槽标成「卡牌脏」）再改朝向**，
  这样 `serverTick` 只会发完整包，客户端拿得到朝向（两个脏标记同时存在时框架只发完整包）。
- **底牌与出牌区不许重合**：两者都摆在「地主面前」，早先各自用一套独立数值（底牌固定缩进 84、
  出牌区偏扇形距离的 55%），椅子离桌心近的时候两条落点会撞在一起——玩家截图上的
  「底牌和出牌重合了」就是这么来的。现在底牌的落点是**由出牌区的落点推出来的**
  （`距离扇形 = 扇形距离 × (1 − PLAY_DRIFT) − BOTTOM_PLAY_GAP`，并至少离扇形
  `BOTTOM_MIN_DRIFT`），于是无论椅子远近都固定错开 0.5 格，且仍然贴着地主那一侧。
  这条不变量由 GameTest 直接断言（「地主的底牌必须留在他自己出的牌后面至少 60 单位」）。
- 这套规则替代了 1.8.0 中途试过的「浮空小字」方案：那个方案需要新的 S2C 包与一整套公告牌渲染，
  实测又大又糊，最后连包带渲染器一起删掉了——**观战的人要的是牌桌，不是标签**。

### 背景音乐是怎么来的

先说清楚一件事：**「欢乐斗地主」那首 BGM 是腾讯的原创音乐作品**，把它的旋律抄进 jar 里分发
属于复制他人音乐作品，所以这个模组不包含它。这里是一段**原创**、按同一路数写的中国风小调：

`DoudizhuBgm` 用原版音符盒音效现场合成一段 4 小节、约 6.4 秒的循环，
**150 BPM 的十六分音符**（2 tick 一格），配器是四声部：

| 声部 | 音色 | 写法 |
| --- | --- | --- |
| 主旋律 | 竹笛（flute） | C 宫五声音阶，四个乐句「起、扬、承、落」，带「答答答」式的同音反复 |
| 伴奏 | 琵琶（banjo） | 每小节 8 个十六分音符的分解和弦，绕根音上下滚动 |
| 低音 | 贝斯（bass） | 每小节第 1、3 拍，第二拍走五度 |
| 锣鼓 | 大鼓（basedrum）/ 板（hat）/ 小锣（bell） | 大鼓踩 1、3 拍，板走后半拍，小锣点小节头 |

- 旋律与配器全部来自几张常量表（`MELODY` / `BAR_ROOTS` / `ARPEGGIO`），编曲在类初始化时算完，
  播放过程不用随机数：同样的 tick 序列一定得到同样的音，不会「每次进牌桌都不一样」。
- 全部走 `SoundSource.MUSIC`，所以原版「音乐」音量滑条直接控制它（刻意不用
  `SimpleSoundInstance.forUI(...)`，那个走 MASTER，会绕过音乐滑条）。
- 音域经过核对：全部 113 个音落在音符盒的 0.500~2.000 倍速内，**没有一个是靠截断夹进去的**。

**换成真实音频**（你自己有那首曲子的授权时）只要两步，代码不用改：

1. 做一个资源包，放 `assets/chartalandlords/sounds/doudizhu_bgm.ogg`，
   并在 `assets/chartalandlords/sounds.json` 里注册 `"chartalandlords:doudizhu_bgm"` 指向它；
2. 进游戏什么都不用按——运行时探测到音效事件就自动改放整首曲目（循环），内置小调同时静音。

探测是双重条件（音效事件已注册 **且** ogg 文件存在），所以不会出现「只注册了 sounds.json
却没放文件」变成一片死寂的情况；每次打开牌局界面都会重新探测一次，加/删资源包或按 `F3+T` 后立刻生效。

## 规则摘要

- **人数与牌堆**：3 人 = 54 张（每人 17 张 + 3 张底牌）；4 人 = 108 张两副牌（每人 25 张 + 8 张底牌）。
- **决定地主**（两种模式，选项里切换；**默认是抢地主**）：
  - **抢地主（默认）**：叫分换成一轮「抢 / 不抢」，底分固定为 1。每次抢都把倍数翻一倍，
    **最后一个抢的人**当地主；一个人都不抢就按下面的「无人叫分」处理。
    第一个抢的人**不**额外翻倍（他相当于普通叫地主），所以抢 n 次记 `n − 1` 次翻倍。
  - **叫分（关掉抢地主模式）**：按座位顺序各叫一次，必须高于当前最高分；叫 3 分立即结束；
    一轮后最高分者为地主；无人叫分则重新发牌（连续两轮无人叫分时指定手牌最强者当地主，避免卡局）。
    叫分有 30 秒超时。
- **明牌 / 加倍**（地主确定之后，选项里可关）：10 秒窗口内，每人有两个**独立的开关**加一个**确认**
  - **明牌**：把手牌公开给所有人（别人桌面上原本的牌背会翻成正面），**个人倍数 ×2**。
    单向开关：牌已经摊在别人眼前，不允许撤回（否则就成了「先亮牌吓人再收回去」）。
  - **加倍**：不公开手牌，**个人倍数 ×2**，确认之前可以反复来回切换。
  - **两个可以同时打开 → 个人倍数 ×4**。界面上「明牌」「加倍」两颗按钮的文案会回显状态
    （`已明牌` / `已加倍`），座位盒在叠满时直接写 `×4`。
  - **确认**结束自己的决定。窗口到点后还没确认的人自动按「当前开关状态」结束，不会有人挂机就把整桌卡住。
- **出牌不设超时**（只有叫分有超时），所以真人可以慢慢想。
- **牌型**：
  - 单张、对子、三张、三带一、三带二。
  - 顺子：5~12 张连续单牌（3~A，不含 2 与大小王）。
  - 连对：3~12 对连续对子（3~A）。
  - 飞机：2~6 个连续三张；可带**等量**的单张（≤5 个三张）或对子（≤4 个三张）。
  - 四带二：四张同点 + 两张单牌（6 张）或两个对子（8 张）。
  - 炸弹：4 张及以上同点；4 人局张数多者压张数少者，张数相同比点数。
  - 王炸：3 人局 = 小王 + 大王；4 人局 = 两张小王 + 两张大王。
- **比较**：同牌型、同长度比关键点数（3 < 4 < … < K < A < 2 < 小王 < 大王）；比较的是**三带/四带里
  张数最多的那个点数**（三带一、三带二、飞机、四带二都按主体比，与带牌无关）。
  炸弹压任意非炸弹；王炸最大，且不能被任何牌压。
- **边界口径**（这些写法各家不一，本模组采用并在代码里显式建模，见 `RuleOptions`）：
  - 飞机带单的「翅膀」可以恰好凑成一对（`333444 + 55` 合法）。
  - 同一手飞机里**不能混用**单翅膀和对翅膀。
  - 四带二的两张单牌**可以**是一对，但四张必须是唯一的四张组，且总张数只能是 6 或 8。
  - 大小王**不能同时**作为同一手的带牌（`3333 + 小王 + 大王` 不合法）。
  - 拆炸弹去凑顺子/连对/飞机在规则上合法，但 AI 会把它排在最后才考虑。
  - 四带二只和同型四带二比大小（不能压别的牌型），但可以被炸弹压。
- **不计分**：只判定谁先出完（地主出完地主胜，任一农民出完农民胜）。
- **发牌**：每次发牌用独立强随机源洗牌，并从牌堆中随机位置抽牌、随机起始座位。

### 计分

叫分即底分（抢地主模式下底分固定为 1），所以「叫 3 分」是有代价的：

- **局倍数**（全场共享）：
  - 每个**炸弹 / 王炸**翻一倍；
  - **抢地主**模式下，抢 n 次再记 `n − 1` 次翻倍；
  - **春天**（地主走完且两个农民一张没出）再翻一倍；**反春天**（农民走完且地主只出过一手）再翻一倍。
- **个人倍数**（只作用于该玩家）：**明牌**、**加倍**各翻一倍，两个都开就是 ×4，所以每人可能是 ×1 / ×2 / ×4。
- **逐对结算**：`单位分 = 底分 × 局倍数`，地主与**每个**农民逐家单独结算，
  这一对的注码是 `单位分 × 地主个人倍数 × 该农民个人倍数`。地主赢就从每家赢走那一份，输就赔给每家。
  3 人局即地主 ±2 份、4 人局 ±3 份，**任何人数、任何个人倍数组合下都是零和**
  （个人倍数只会放大对应那一对，不会凭空造分）。
- 结算播报在聊天栏（含底分 / 炸弹 / 抢次数 / 局倍数 / 有几人有个人倍数），
  **跨局累计分数**显示在座位条第二行右侧。可以在牌局选项里关掉计分（只判胜负）。

> **累计分数是跨局的**：Charta 每开一局都会新建一个 `Game` 实例
> （`CardTableBlockEntity.startGame`），而且 `getOrderedPlayers()` 每次开局都会 `shuffle` 决定起始座位，
> 所以分数既不能放实例字段、也不能按座位号存。实现上按「**牌桌身份**（座位所在椅子的集合，与轮转无关）
> + **玩家身份**（实体 UUID，退化时用名字）」存，所以：
>
> - 第 1 局全程显示 `0`（还没结算过），**第 2 局起能看到上一局累计的分数**；
> - 同一批人换到别的牌桌坐，是另一张记分板；换人（座位集合变化）也会重新开始；
> - 记分板表有上限（64 张牌桌），超出后淘汰最久没用过的，不会无限增长。

### AI 难度档位

难度不是三份策略代码，而是**一张权重表**（`AiProfile`）传进同一个 `AiPolicy`。
三个档位在四个地方真的打出不同的行为：

| 档位 | 叫 1/2/3 分的门槛（相对基线） | 抢地主门槛（首个 / 每个已抢 / 最后一人减免） | 明牌 / 加倍门槛（相对基线） | 动炸弹 | 开始封杀 | 领炸弹 | 领 2/王 | 拆牌 | 超压 | 首出评估上限 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 保守 `conservative` | +5 / +9 / +13 | +4 / +3 / −2 | +10 / +5 | ≤1 张 | ≤1 张 | 2600 | 900 | 160 | 90 | 24 |
| 1 均衡 `balanced` | +3 / +7 / +11 | +2 / +2 / −2 | +8 / +3 | ≤2 张 | ≤2 张 | 2000 | 600 | 120 | 40 | 32 |
| 2 激进 `aggressive` | +1 / +4 / +8 | +0 / +1 / −3 | +6 / +1 | ≤3 张 | ≤3 张 | 900 | 250 | 70 | 10 | 40 |

方向全部单调：档位越高越敢叫、越敢抢、越敢亮牌加倍、越早动炸弹、越早开始封杀。

**门槛为什么是「相对基线」而不是绝对分**：控场分的绝对值和手牌张数强相关——实测随机发 20 万手牌，
3 人局 17 张的均值是 **2**，4 人局 25 张的均值是 **12**（多出来的 2 / 王 / 炸弹更多）。
门槛写成绝对值时，4 人局会出现「95% 的手牌都够叫 1 分、近一半够叫 3 分」的退化现象，
而且 AI 会几乎人人明牌。基线取 `2 + (手牌数 − 17) × 5 / 4`（17 → 2、20 → 5、25 → 12、33 → 22，
与实测均值相差不超过 2 分），叫分 / 抢 / 明牌 / 加倍的门槛全部相对它来量。

实测触发概率（每格 4 万次发牌，AI 全档位；个人倍数是两个独立开关，所以还有一列「两个都开」）：

3 人局（农民 17 张 / 地主 20 张）：

| 档位 | 明牌 | 加倍 | 其中 ×4（两个都开） |
| --- | --- | --- | --- |
| 0 保守 | 3% | 18% | 3% |
| 1 均衡 | 6% | 32% | 6% |
| 2 激进 | 12% | 50% | 12% |

4 人局（农民 25 张 / 地主 33 张）：均衡档 12% / 32%（农民视角）、23% / 47%（地主视角）；
激进档 18% / 44%、30% / 58%。地主手牌多 8 张，控场分天然更高，所以更愿意亮牌加倍——
这是符合直觉的。

其他实测数据：

| 场景 | 保守 | 均衡 | 激进 |
| --- | --- | --- | --- |
| 3 人局叫分「无人叫」 | 52% | 23% | 4% |
| 3 人局抢地主「无人抢」 | 27% | 5% | 0% |
| 3 人局抢 2 次以上的概率 | 5% | 26% | 78% |
| 4 人局抢地主「无人抢」 | 22% | 10% | 3% |

「无人抢」的比例刻意压在 30% 以内：连续无人抢会触发重新发牌，太多就变成在洗牌而不是在打牌。

「只调风格、不动规则」由三重断言守着：换档前后 `RuleOptions` 必须逐项一致；三档都要能打完一整局；
以及**不紧急的局面下三档必须挑同一手「最便宜的安全压牌」**——难度不该让低难度打出明显错误的牌，
差别只体现在叫分、抢、亮牌、炸弹时机和「对手剩几张才算危险」上。

### AI 出牌逻辑的三个改进

这三条是「以前明显打错、现在必须打对」的具体决策，全部用构造牌面钉死在
`PlayHarnessMain` 第 7 节，回归会立刻失败：

1. **封杀**：对手只剩一两张（具体几张由档位的「开始封杀」决定）时，跟牌不再出最小可压，
   而是改出「外面根本压不动」的最小候选，找不到就出**最大**的那手；
   首出则优先出对手一只手接不住的牌型（张数比他的手牌还多），只能出单张时反过来优先出大牌。
   以前手里是 `5 Q 2`、对手剩 1 张、上家出 4，AI 会乖乖出 5，对手随手一张 6 就走完了。
2. **残局保形**：手牌 ≤10 张时，跟牌会在「干净候选」里顺带评估走完之后还剩几手，
   明显更少手时才推翻原选择。以前手里是 `7 8 9 10 J` 加一张 A，跟一张单牌时会出 7 把顺子拆成五张散牌；
   现在出 A，顺子整整齐齐留到下一手走完。
3. **抢地主的代价意识**：抢的门槛随「已经有多少人抢过」抬高（每多一人倍数翻一倍），
   自己是最后一个决定的人时降低（没人能再抬价）。以前只是拿叫分门槛顺手判断，
   会导致「越抢越勇」这种明显不合理的判断。

`check_assets.py` 的存在理由是 **Charta 的牌面格式是私有的**：`.mccard/.mcsuit` 是

1. 把 `back.mccard` / `blank.mcsuit` **解码回像素**，与 `gen_assets.py` 里的设计图**逐字节对拍**（当前差异 0）；
2. 两副牌堆 JSON 的张数（54 / 108）、字段完整性，以及「两副牌正好是 54 种各 2 张」；
3. 三张图标（选桌 70×70、模组 logo 140×140、项目图标 700×700）的尺寸、透明度与「模组 logo 确实是
   选桌图标同一套美术」；
4. `pack.mcmeta`（模板 + 展开后的产物）：`pack_format` 是整数、`${mod_name}` 真的被替换成模组名。

### 为什么规则引擎不依赖 Minecraft

`RuleEngine` / `HandShape` / `AiPolicy` / `RuleOptions` / `Combo` / `ComboType` **不引用任何 Minecraft 或
Charta 类型**，只吃 `int[]` 点数数组（3..10 = 3..10，J/Q/K/A = 11/12/13/14，2 = 15，小王 = 16，大王 = 17）。
`DoudizhuRules` / `DoudizhuAi` 只是 `Card ↔ 点数` 的适配层。

好处是：整副规则与 AI 策略可以在**类路径上完全没有游戏**的情况下穷举校验（`tools\logic-check.ps1`，
当前 171 + 20 + 249 = **440 项断言**全绿，含对随机手牌的 fuzz，以及
「抢地主 / 明牌 / 加倍」的 4536 组倍数零和穷举），改规则时不必启动 Minecraft。

## 更新记录

### 1.8.0

**修掉两个点击问题**

- **「点第二行的牌，结果第一行的牌进了出牌区」**：`resolveCardIndex` 的扇形算术在边缘
  （某张牌左侧、或两张牌的缝里）会返回 `-1`，调用方只好退回「框架记录的悬停牌号」——
  而那个牌号属于**框架认为**鼠标悬停的那个槽，在上下行叠压的牌带里可能正好是**另一行**，
  于是 slotId 和 cardId 来自两个不同的槽，拼出一张不在你点的那一行里的牌。
  现在 `resolveCardIndex` 只要落在行内就**一定**返回一个合法下标（必要时吸附到最近的一张），
  并且彻底去掉了跨槽的 `hoveredCardId` 兜底。
- **「点上一手和底牌重叠的部分会拿起上一手的牌」**：`DoudizhuMenu` 里上一手的展示行
  是用 `new GameSlot(...)` 直接造的，而默认的 `canRemoveCard` 是 `!isEmpty()` —— 也就是**允许**拿走。
  框架自带一条「命中任意卡槽就把牌拿在鼠标上」的流程，于是上一手牌真的会被拿起来跟着鼠标跑。
  现在所有展示槽统一走只读槽（`canInsertCard` / `canRemoveCard` 都返回 false），
  并且点在自己画的牌带上会直接吃掉这一下，不让框架的流程插手。

**牌桌摆位：世界里的信息改用「牌的位置」表达**

- **各座位的手牌扇形整局保留**：以前第一轮出牌结束就把扇形和底牌一起收走，于是牌局进行到一半时
  桌面上只剩一张上一手牌，看上去像没人打牌。现在扇形会被**推到椅子那一侧**（不再挡桌面），
  所以整局都能留着——随时低头就知道每家还剩几张。
- **底牌摆到地主面前**：这是真实斗地主的摆法，那三张公开的牌同时就是「谁是地主」的标记，
  桌心也空出来给上一手牌。
- **轮到谁就把谁的扇形推向桌心**：换人时上一家自动退回（客户端位置是插值的，看上去是滑过去）。
  偏移量记在「基准位置」上（`fanRest`），所以跟执行顺序无关，重新发牌不会越推越远。
- **上一手牌往出牌者那一侧偏 26%，并按出牌者的朝向摆放**：牌本身不写名字、也不再所有人朝同一个方向，
  观战的人靠「偏向哪边 + 朝哪边」看出这手是谁打的；收桌（其余人都不出）时回到桌心。
- **摆位基准改成一个固定的「桌心」常量**：以前扇形推出、底牌缩进、轮到谁推多远都是拿 `playArea`
  的**当前位置**当中心，而这一版让上一手牌会动了——于是同一局里轮到同一个人的位移会跟着上一手牌
  一起变（GameTest 抓到「推出去 44、退回 42.66」）。现在三处都改成固定桌心。
- **扇形不再往外推（`FAN_PUSH_OUT` 38 → 0）**：推出去之后只有「轮到谁」那一家看着像待在牌槽里，
  其余三家都偏到桌外（玩家反馈原话）。现在四家都规规矩矩待在自己的槽位，「轮到谁」只做 0.19 格的内推。
- **上一手牌挪到「出牌者面前」（`PLAY_DRIFT` 0.26 → 0.55）**：0.26 只是「稍微偏一点」，看不出是谁的牌；
  现在过了中点，明确属于出牌者那一侧，同时仍然不贴到他的扇形上。
- **底牌改成「由出牌区推出来」**（不再是一个独立常量）：两者都摆在地主面前，椅子离桌心近的时候
  原先会重合成一堆（玩家截图：「底牌和出牌重合了」）。现在底牌固定退到出牌区后面 0.5 格、
  并贴着地主那一侧，无论椅子远近都错得开——GameTest 断言「地主的底牌必须留在自己出的牌后面 ≥60 单位」。

     自己这个视角里别人的牌扇基本被面板挡住——「别人看不到牌」看到的就是这个；
  2. 界面里原本**没有任何**展示别人手牌的地方（座位盒只有「剩 N 张」）。
- 修法：新增**明牌展示行**——每个座位一行，服务端只给明牌过的座位填整手正面牌，
  其余座位保持为<b>空槽</b>，而 Charta 的 `GameScreen` 对空卡槽根本不创建控件，
  所以没人明牌时这几行不占任何画面，布局与以前完全一致。牌由框架自己画，是真卡面而不是文字。
- 展示槽放的是**正面副本**（`Card.copy()`），清空它不会动到真手牌——这一点由 GameTest 断言。
- 另外把整手牌再发一条到聊天栏（`明牌明细 —— X：…`），窗口太矮画不下时也有记录，
  而且会进 Charta 的历史界面。
- 记牌器会自动给明牌展示块让位（可用高度不够时退化成 1 行 15 格），不会叠在一起。

**协议**

- 协议端口 **`"6"` → `"7"`**：明牌展示行注册在所有牌带**之前**（它位置最高，
  按「屏幕位置越靠下越晚绘制」必须最先画），于是所有既有卡槽序号整体后移，
  `SelectCardPayload.slotId` 的含义随之改变——这正是本模组写明要提升版本号的情形。

**验证**

- GameTest 30 → **31 个**：新增「明牌之后界面展示槽必须有整手正面牌、逐张点数一致、
  清空展示槽不影响真手牌、没明牌的座位保持为空」；
  并把布局用例里写死的「底牌必须是 0 号槽」改成真正的不变量（底牌比上一手先画），
  再补上明牌行的槽位↔座位映射与上下顺序断言。

### 1.6.0

**玩法 / 手感**

- **新增手牌手动排序**：按住手牌拖到别的位置即可调整顺序。一旦拖过，该座位切换到
  **手动牌序**——出牌与选牌只做「删掉那张」，**整只手牌不再重排**，位置不会每出一手就跳一次。
  `整理` 按钮清掉手动牌序、按点数重排一遍。
- **修掉「地主新到手的牌无法调整牌序」**：地主拿底牌时如果正在用手动牌序，三张新牌现在
  **接在手牌末尾**并给出提示（以前会直接整手重排，把玩家摆好的顺序冲掉），拖走或整理都行。
- **出牌不再触发重排**：出牌、选牌都不再调用排序；发布时排一次、撤回时按点数插回原位，
  所以出牌前后手牌在屏幕上的位置基本不动。
- **非法出牌保留选牌**：以前点错一次就把选牌整批退回手牌、得从头再选；现在选牌原地保留，
  拿掉一张就能直接重试（机器座位仍然退回，避免抱着非法牌死循环）。
- **新增快捷键**：`回车` = 出牌、`空格` = 不出。按钮列在屏幕右侧，每次都要把鼠标横跨半个屏幕，
  这两个键覆盖了绝大多数操作；每局第一次轮到人类玩家时会提示一次，不刷屏。

**显示**

- **新增逐座位的「表态牌子」**：抢地主模式显示 `抢` / `不抢`，叫分模式显示 `N分` / `不叫`，

- **抢地主状态行补上「当前地主候选」**：`抢地主：X（已抢 2 次）  当前地主候选：Y`，
  没人抢时写「还没有人抢」——叫分 / 抢地主还没结束之前 `landlordSeat()` 还是 -1，
  以前那段时间界面根本不知道是谁的。
- 座位标记位扩到 5 位（bit3 = 已抢、bit4 = 已表态），并新增逐座位的叫分数据槽。

**协议**

### 1.5.0

**玩法**

- **明牌与加倍可以同时选**（个人倍数 ×4）。这一阶段从「一人一次二选一」改成
  **两个独立开关 + 确认**：
  - 开关**按下即生效**，所以玩家在确认之前就能在状态行看到自己当前押了多少（`我的个人倍数 ×4`）；
  - **明牌是单向的**——牌已经摊在别人眼前，不允许撤回（否则就是「先亮牌吓人再收回去」）；
    界面上的「明牌」按钮按过之后变成 `已明牌` 并变灰；
  - **加倍可以反复来回切换**，按钮文案在 `加倍` / `已加倍` 之间随状态变化；
  - 「确认」结束自己的决定，窗口到点没确认的人按**当前开关状态**结束。
- 座位盒在叠满时直接显示 `×4` 徽章（亮橙），比只写「明倍」两个字更清楚。
- 结算本来就支持「逐座位个人倍数指数」，所以 ×4 只是指数为 2 的情形，一行逻辑都没改
  （纯逻辑层早就有 `reveal + double = x4` 的断言）。

**协议**

- 协议端口 **`"4"` → `"5"`**。动作序号与 payload 线格式**都没变**，变的是
  `DoudizhuAction.DECLARE_PASS` 的**语义**（「跳过」→「确认并结束我的决定」）；
  按本模组写明的规则，语义变化同样要提升版本号。
- `DoudizhuGame` 新增 `personalFactor(seat)` / `personalDoublings(seat)` / `canDeclare(seat)` /
  `canReveal(seat)` / `isDeclared(seat)`；`DoudizhuMenu` 新增 `canRevealNow()` / `canDoubleNow()` /
  `myPersonalFactor()` / `seatPersonalFactor(seat)`。

**验证**

- GameTest 25 → **26 个**：明牌 + 加倍叠加后 `personalFactor == 4`、重复按「明牌」是空操作、
  「加倍」可以来回切换、确认之后不能再改开关、一个座位确认不会提前开始出牌阶段，
  以及**结算里的个人倍数必须等于两个开关算出来的值**（整局仍然零和）。
- 实测「两个开关都开」的触发率：3 人局均衡档 6%（激进 12%），即「亮牌 + 加倍」是稀有但确实会发生的高光动作。

### 1.4.0

**玩法**

- **抢地主改为默认开启**：默认牌局就是「一圈抢 / 不抢 → 明牌 / 加倍 → 出牌」，底分固定 1。
  想回到经典 1/2/3 分叫分，在牌局选项里把「抢地主模式」关掉即可（选项与动作编号都没变，
  所以**协议端口仍是 `"4"`**，同一大版本内新旧客户端可以互通）。

**AI**

- **抢地主决策独立成一条策略**（`AiPolicy.chooseGrab`）：门槛随「已经有多少人抢过」抬高
  （每多一人倍数翻一倍，用一个中等牌去当地主越来越不划算），自己是**最后一个决定**的人时降低
  （没人能再抬价了）。以前只是拿叫分门槛顺手判断，会出现「越抢越勇」这种明显不合理的判断。
- **三个难度档位多出两条真正的差异轴**：抢地主意愿与明牌 / 加倍意愿，加上原本的叫分门槛、
  炸弹触发线，以及新增的「开始封杀」触发线，一共五个维度。实测触发概率见
  「AI 难度档位」一节（3 人局抢地主「无人抢」：保守 27% / 均衡 5% / 激进 0%；
  明牌率 3% / 6% / 12%）。
- **修掉一个标定错误**：控场分门槛以前写的是绝对分，而控场分和手牌张数强相关——
  4 人局 25 张的均值就有 12，于是 4 人局「95% 的手牌都够叫 1 分、近一半够叫 3 分」，
  AI 也几乎人人明牌。现在全部改成**相对基线**（`2 + (手牌数 − 17) × 5 / 4`，
  用 20 万手随机牌标定，误差 ≤2 分），两种人数下的触发概率才一致。
- **新增封杀逻辑**：对手只剩一两张（几张由档位决定）时，跟牌改出「外面压不动」的最小候选，
  实在没有就出最大的；首出优先出对手一只手接不住的牌型，只能出单张时反过来优先出大牌。
  以前手里是 `5 Q 2`、对手剩 1 张、上家出 4，AI 会乖乖出 5，对手随手一张 6 就走完了。
- **新增残局保形**：手牌 ≤10 张时，跟牌会在干净候选里顺带评估「走完之后还剩几手」，
  明显更少手时才推翻原选择。以前手里是 `7 8 9 10 J` 加一张 A，跟单牌时会出 7 把顺子拆成散牌。
- 明确区分「风格」与「水平」：不紧急的局面下三档必须挑同一手最便宜的安全压牌，
  难度只改叫分 / 抢 / 亮牌 / 炸弹时机 / 紧迫感，不会让低难度打出明显错误的牌（由断言守着）。

**验证**

- 纯逻辑断言 374 → **440 项**：新增控场分基线标定（随机手牌的平均 margin 必须接近 0、
  两种人数下的叫分与抢概率必须落在同一区间）、抢地主决策的单调性与档位排序、
  档位行为差异率（不紧急局面必须一致、紧急局面必须分歧 ≥10%），以及三条封杀 / 残局的构造牌面。
- GameTest 24 → **26 个**：新增「默认就是抢地主模式」「叠满的个人倍数进结算」；
  四个测叫分语义的老用例显式关掉抢地主。

### 同点数不能互压（针对「AI 用 10 压 10」的反馈）

三层验证都证明当前实现不会用同点数互压，任一层回归都会立刻失败：

| 层 | 覆盖 | 位置 |
| --- | --- | --- |
| 纯规则引擎 | 全部点数 × 全部可成型牌型（单/对/三/炸/三带/四带/顺子/连对/飞机，两套规则集）**自压**必须为 false | `PlayHarnessMain` 第 4 节 |
| 生成器 + AI | 跟单张时生成器不得给出同点数候选；AI 手持 10 面对单张 10 的 60 次强制决策全部合法 | 同上 |
| 集成 / 落桌 | 回放 20 整局（3 人 + 4 人），**每一手真正落桌的牌**都必须严格压过上一手，且本身是合法牌型 | `DoudizhuGameTests.everyCommittedPlayBeatsTheLast` |

若玩家仍看到「10 压 10」，最可能的原因是**牌带只露出牌的窄条**：四张 10 的炸弹（合法）与一张 10
在缩略图上几乎一样。为此：

- `上一手` / `出牌区` 标签下面现在直接写出**牌型与张数**（例如 `炸弹 ×4`）。
- 服务端对**机器座位**投递上来的非法出牌会留一条 `Rejected illegal play from ...` 的 WARN 日志
  （人类误点不刷日志，只给聊天提示）。下次再有反馈，日志里就能直接看到那一手牌。
